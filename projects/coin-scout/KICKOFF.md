# coin-scout(狙い目コイン通知ボット)キックオフ

> **履歴資料（2026-09-06にv2へ改訂）**: この文書は初期仕様の証跡として保持する。
> 「エントリー候補」「ロング/ショート傾斜」等は現行通知仕様では採用しない。
> 現行の指標・保存・通知定義は `README.md` と `LOGIC_VERSION=observability-v2.0` を正とする。

## 目的
「今どのコインが動き始めているか」を自分でチャートを巡回せずに把握する。
既存のhyperliquid-report(自分のポジション・成績の評価)の対になる、
**エントリー候補の入口**を自動化するボット。

## 仕様

- **入力**(すべて無料・APIキー不要の公開API):
  - Hyperliquid info API — 上場銘柄一覧、価格、24h出来高、ファンディングレート、OI、ローソク足
  - Binance / Bybit の公開ティッカーAPI — 24h出来高(USD換算)
- **監視対象**: Hyperliquid上場銘柄のうち、BinanceまたはBybitで24h出来高 $10M 以上の銘柄
  (= 流動性フィルタ。2025年の損失源だった超マイナー銘柄を構造的に除外)
- **検知ロジック**(3本柱、各銘柄をスコアリングして上位を通知):
  1. **出来高・価格の急変動** — 24h出来高が直近7日平均比で急増(暫定: 2倍以上)+ 価格変動が平常ボラ比で大きい
  2. **ファンディング/OIの偏り** — ファンディングレートの極端な偏り(暫定: 年率換算 ±30%以上)、OIの急増(暫定: 前回スキャン比 +20%以上)。ロング/ショートどちらに傾いているかを明記
  3. **新規上場検知** — Hyperliquidの銘柄一覧を前回スキャンと差分比較し、新規上場を検知(イベント系は損失源だった経緯があるため、通知には注意書きを添える)
- **出力**: Discord Webhookへ1日2回のダイジェスト通知(既存と同じWebhook運用)。
  各銘柄につき「銘柄 / 検知理由 / 現在価格・24h変動 / 出来高倍率 / ファンディング / 方向の示唆」を1〜2行で。
  深夜帯の抑制はしない(ユーザー判断)。
- **使う場面**: 朝と夜にDiscordを見て、その日の監視候補を決める
- **やらないこと**:
  - 自動売買・発注(通知のみ。売買判断は人間)
  - テクニカル指標ベースの検知(MA・RSI等は今回のスコープ外)
  - リアルタイム監視(5分間隔などの高頻度化はしない — 高頻度回転の誘発を避ける)
  - 「買い推奨」の断定(あくまでスクリーニング結果の提示)

## 完成の定義

### ツールの正しさ(作った直後に検証)
- [ ] 監視対象リストが手動確認と一致する(Hyperliquid上場 ∩ Binance/Bybit出来高$10M+)
- [ ] ファンディング・出来高・OIの数値がHyperliquidのUI表示と一致する
- [ ] 出来高急増・ファンディング偏り・新規上場それぞれが、意図した閾値で発火する(過去データ/擬似データで確認)
- [ ] 該当銘柄ゼロの回でも「該当なし」の短い通知が届く(ボットの生存確認を兼ねる)
- [ ] API障害時に落ちて無音にならず、エラーがDiscordに通知される
- [ ] 朝・夜の定刻にGitHub Actionsが実行される

### 成果(運用して評価)
- 通知された銘柄が実際に「その後動いたか」を数週間観察(通知に納得感があるか)
- チャート巡回の時間が減ったか
- ※ 勝てるかどうかはこのツール単体の責任範囲外。入口の発見を速くするのが仕事

## マイルストーン
1. **データ取得部** — HL銘柄一覧+Binance/Bybit出来高で監視対象リストを作る
   → 確認方法: リストを出力し、銘柄数と顔ぶれが妥当か目で確認
2. **検知ロジック** — 3本柱のスコアリング実装。状態ファイル(前回スキャンのOI・銘柄一覧)の保存
   → 確認方法: 現在の実データでどの銘柄が発火するか出力し、閾値の妥当性を確認
3. **Discord通知** — ダイジェスト整形+テスト送信
   → 確認方法: テスト通知がDiscordに届き、読みやすいことを確認
4. **定期実行** — GitHub Actionsで朝・夜のcron設定、状態ファイルの永続化、エラー通知
   → 確認方法: 数日運用して定刻に届くこと・内容が安定していることを確認
